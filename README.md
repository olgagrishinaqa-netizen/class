# Информационная система управления школьным классом (Serverless SaaS)

Репозиторий содержит исходный код веб-приложения для автоматизации взаимодействия родительского комитета и родителей класса, а также декларативное описание облачной инфраструктуры (IaC) и конфигурацию конвейера непрерывной интеграции и доставки (CI/CD) [^image_-4O3RO.png].

---

## 🛠 1. Архитектурный стек и технологии

* **Backend:** Python 3.11 / Flask (WSGI-приложение) [^Tilda Publishing].
* **База данных:** Yandex Managed Service for PostgreSQL (Serverless-режим) [^1.1.3].
* **Контейнеризация:** Docker / Docker Buildx [^image_-4O3RO.png].
* **Инфраструктура как код (IaC):** Terraform 1.5.7 [^image_-4O3RO.png].
* **Платформа автоматизации (CI/CD):** GitHub Actions (Ubuntu-24.04 runners) [^image_-4O3RO.png].
* **Облачная среда:** Yandex Cloud (экосистема Serverless) [^image_200zex.png].

## 💻 3. Инструкция по локальному развертыванию (Для разработчика)

Локальный запуск используется для отладки интерфейса и тестирования логики без затрат облачных ресурсов.

### Шаг 3.1. Подготовка окружения
1. Клонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone https://github.com
   cd class
   ```
2. Разверните и активируйте виртуальное окружение Python:
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   ```
3. Установите локальные зависимости:
   ```bash
   pip install -r requirements.txt
   ```

### Шаг 3.2. Локальный запуск приложения
Для локальной работы с персистентным хранением передайте параметры подключения к СУБД через переменные окружения ОС (или временно переключите код на работу с JSON-заглушкой):
```bash
export DB_HOST="ваш_хост_бд"
export DB_NAME="class_db"
export DB_USER="db_admin"
export DB_PASSWORD="ваш_пароль"
python app.py
```
Приложение станет доступно по адресу: `http://127.0.0`.

## 🚀 4. Инструкция по автоматическому деплою (CI/CD Production)

Конвейер развертывания полностью автоматизирован по принципам GitOps: отправка кода в ветку `main` инициирует автоматическую доставку изменений в облако [^image_-4O3RO.png].

### Шаг 4.1. Настройка панели управления GitHub (Secrets & Variables)
Для авторизации робота-сборщика добавьте следующие параметры в настройки репозитория (**Settings -> Secrets and variables -> Actions**) [[^image_K-ngc2.png], [^image_R_Buu9.png]]:

* **Вкладка Secrets (Зашифрованные переменные):**
  * `YC_SA_JSON_CREDENTIALS`: Полный приватный JSON-ключ авторизации сервисного аккаунта Yandex Cloud [^image_200zex.png].
  * `DB_PASSWORD`: Пароль администратора СУБД PostgreSQL.
* **Вкладка Variables (Неконфиденциальные параметры):**
  * `YC_FOLDER_ID`: Идентификатор каталога в Yandex Cloud.
  * `YC_REGISTRY_ID`: Идентификатор реестра в Yandex Container Registry.
  * `YC_SERVICE_ACCOUNT_ID`: Идентификатор облачного сервисного аккаунта.

### Шаг 4.2. Запуск доставки изменений
Любое изменение кода фиксируется через Git и отправляется на сервер:
```bash
git add .
git commit -m "Feature: deploy to production"
git push origin main
```

### Шаг 4.3. Логика работы конвейера (GitHub Actions Workflow)
1. **Качество кода (Job: `lint-and-test`):** Запускается статический анализатор кода `flake8`, проверяющий синтаксис Python-скриптов.
2. **Сборка артефакта (Job: `build-and-deploy`):**
   * Скачивается и инициализируется Yandex Cloud CLI [^image_ke4wY4.png].
   * Docker-сборщик Buildx компилирует образ приложения с уникальным тегом (`Git Short SHA`) и кэшированием слоев (`type=gha`), после чего отправляет его в приватный облачный реестр.
   * Нативный Terraform подхватывает собранный тег образа, безопасно маскирует пароли базы данных (`sensitive = true`) и разворачивает облачный Serverless-контейнер, выводя готовую публичную ссылку (`website_url`) прямо в логи деплоя.
